# Ontic MVP — Stochastic Specification Compiler

**Date:** 2026-08-22
**Author:** Randy Smits-Schreuder Goedheijt
**Status:** Approved (session of 2026-08-22)

## 1. Thesis

Ontic inverts compilation: the user writes *specification* (signatures,
invariants, examples); a local transformer (Mellum2, served through VITRIOL's
llama-server) *stochastically proposes* implementations; a fully deterministic
sieve discards implementations that are invalid, violate contracts, overfit
the visible examples, or fail held-out evidence. The surviving fastest
candidate is emitted as MLIR text, cached content-addressed, and composable:
larger wishes call verified vault symbols as opaque contract-bound calls.

Division of labour (hard rule):

> **Prove algorithmically whatever can be algorithmically proven. The LLM
> does stochastic generation only. It never validates, never ranks, never
> decides.**

## 2. Spec format v0 (.ont)

```
fn Ledger.total(items: List<Int>) -> Int
  | res >= 0                  // invariant: guides forge AND bounds the probe oracle
  => [1,2,3] -> 6             // transparent example — forge sees it
  ?? [7,8,9] -> 24            // opaque example — forge never sees it
```

Opaque policy: explicit `??` wins; otherwise auto-hide floor(50%) of `=>`
examples when ≥4 total examples exist. Forge prompts contain only the
transparent set.

## 3. Sieve pipeline (all stages deterministic)

| # | Stage | Mechanism | Kill condition |
|---|-------|-----------|----------------|
| S1 | Parse | recursive-descent parser mirroring the GBNF grammar | malformed |
| S2 | Well-formedness | sketch typechecker | type error |
| S3 | Transparent eval | tree-walking interpreter | any example fails |
| S4 | Held-out eval | interpreter on opaque set | any fail ⇒ overfit |
| S5 | Probe eval | xorshift-generated randoms from type domains ∩ invariants | violation |
| S6 | Overfit shape scan | static AST analysis: constant-guard ratio vs transparent literals, output-literal table shape | suspicious |
| S7 | Bench rank | interpreter timing on sized input | — |

Post-sieve: winner lowered to MLIR (`lower/`), validated by `mlir-opt` when
available (best-effort), stored in vault keyed by SHA-256 of canonical wish.

Interpreter-first rationale: the oracle must not depend on external binaries.
MLIR validation enhances; it never gates correctness of the sieve.

## 4. Modules

```
src/
  main.rs    CLI: check / solve / bench / vault ls
  wish.rs    .ont parser + auto-split logic
  sketch.rs  candidate AST + grammar (GBNF string mirrored by parser)
  check.rs   S2 typechecker
  interp.rs  evaluator (the oracle)
  probes.rs  PRNG + probe generation + invariant filtering
  overfit.rs S6 static scanner
  sieve.rs   pipeline orchestration + machine-readable failure reasons
  lower.rs   sketch AST → arith/scf/memref MLIR text
  forge.rs   llama-server client: K parallel samplers, GBNF-constrained
             /completion calls, one error-feedback round
  http.rs    hand-rolled HTTP/1.1 keep-alive client (std only)
  rng.rs     xorshift64*
  sha256.rs  FIPS-compatible SHA-256 (self-contained addressing)
  vault.rs   content-addressed store + manifest
```

Dependencies: `serde`, `serde_json` only. HTTP, RNG, hashing hand-rolled —
fully self-contained.

## 5. Forge optimization constraints

- Hand-rolled HTTP/1.1 with keep-alive; no TLS (localhost).
- K parallel workers (default 32), one TCP connection per worker, reused.
- GBNF grammar constrains every sample server-side: parse failures ≈ 0.
- Prompt = signature + invariants + transparent examples + vault dep
  signatures. No prose padding.
- One feedback round: sieve failures distilled to machine-readable reasons
  appended to retry prompt.

## 6. Milestones

- **M0 (this scaffold):** full sieve spine, hand-written candidates, vault,
  CLI, ledger example. Gate: lookup-table overfit candidate rejected, honest
  fold accepted.
- **M1:** forge live against VITRIOL llama-server; total() solved from spec.
- **M2:** vault composition (`use` of verified symbols as opaque calls).
- **M3:** `prop` user properties + bounded Z3 fragment (opt-in).
- **M4:** affine/vector pass-through on winners, measured A/B.

## 7. Honesty requirements

- "Most efficient" = fastest *measured among survivors*, never claimed global
  optimum.
- Probe strength is bounded by invariant strength; weak invariants leak
  overfit. Documented per-wish via `ontic check`.
- S1–S7 is a filter, not a proof. Undecidable postconditions stay undecidable.
